# Classic NTSC compatibility

This project uses an original presentation and a clean-room simulation. The reference for gameplay behavior is the 1989 North American Nintendo NES release. One `Game::tick` is one logical frame at approximately 60.0988 Hz. Board coordinates use a top-left origin: x is 0–9, y is 0–19.

The documented ROM disassembly is used as behavioral evidence, not as source to translate line by line. The [original instruction manual](https://www.world-of-nintendo.com/manuals/nes/tetris.shtml), [MeatFighter's independent reverse engineering](https://meatfighter.com/nintendotetrisai/), [modern bug analysis](https://negative-seven.github.io/tetris_explained/), and [annotated disassembly](https://github.com/CelestialAmber/TetrisNESDisasm) are the main references.

## Scope and remaining differences

- The game intentionally uses original graphics, audio, interface, and success screens. It does not reproduce cartridge assets.
- Exact B-Type tile *occupancy*, three palette classes, and RNG consumption are modeled. The numeric cell IDs 1–3 are project palette classes rather than Nintendo tile IDs.
- A directly supplied seed is deterministic; an actual console reaches a starting state after a variable number of menu frames. A full power-on/menu trace is needed to match that state exactly. The game's piece counter starts at zero on reset for the research API, while the original cartridge's counter can persist across games in one powered-on session.
- An NMI wait occurs between the initial preview selection and B-Type board generation, and again after each generated board row. `Game::reset` and the board helper account for these advances; exact power-on timing still requires a full menu trace.
- The original's soft-drop BCD scoring has anomalies dependent on existing score digits. Strict mode currently uses a normal integer bonus, so strict soft-drop score is approximate; line-clear score and cap are separately verified.
- The original playfield uses a 256-byte buffer, with rare offscreen aliasing and top-row bugs. This engine stores two separate hidden rows for common near-ceiling behavior. Exact offscreen aliasing is not modeled.
- The desktop HUD shows B-Type lines remaining, derived from the core's cleared-line counter.
- The desktop holds a separate visual board during line-clear animation, matching the cartridge's distinction between already compacted playfield RAM and the still visible pre-clear image. This presentation uses original colors and drawing code, not cartridge graphics. The `--screenshot` option saves a BMP of the first rendered frame for inspection.
- Extreme-level CPU crashes, palette bugs, and malformed display digits are outside normal Extended gameplay. Strict mode keeps the numerical cap and wrap without intentionally crashing the process.

## Source conflict resolved

Some descriptions call NES piece selection an eight-sided draw followed by a uniform seven-sided retry. That is a useful probability summary, but it omits the high RNG byte, spawn count, previous **orientation** ID, and an LFSR advance on retry. The annotated ROM routine and MeatFighter's analysis agree on the detailed arithmetic, which this project uses. The shorthand "lowest three RNG bits" in some accounts refers to the lowest bits **of the high byte**, as verified against the ROM instructions.
